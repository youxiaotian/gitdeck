# 安全与信任边界

## 威胁模型

GitDeck 是可以读写仓库的本地工具，主要安全目标：

1. 不监听远程网络地址。
2. 浏览器不能提交任意 shell 命令。
3. 不能通过路径访问已注册仓库之外的文件。
4. 不能全局关闭 Git 所有权检查。
5. 不能静默覆盖其他程序刚修改的文件。
6. 工作区维护不能删除仓库目录。

## 网络边界

- HTTP 服务只绑定 `127.0.0.1`。
- 每次进程启动生成新的随机 `SESSION_TOKEN`。
- 所有 `/api/*` 请求必须携带 `X-GitDeck-Token`。
- 带 `Origin` 的请求必须解析为本机回环地址。
- 不返回 CORS 头。

## 命令执行

- 所有命令通过 `spawn(command, args, { shell: false })` 执行。
- Git 动作来自固定 `switch`，前端不能传任意命令或任意参数数组。
- `GIT_TERMINAL_PROMPT=0` 避免交互式凭据提示卡住服务。
- 远端认证依赖用户已有的 Git credential helper。

## 路径校验

`validateRepositoryPath()`：

- 统一路径分隔符；
- 拒绝 NUL；
- 拒绝绝对路径；
- 相对仓库根解析；
- 要求结果仍在仓库内；
- 拒绝 `.git` 路径。

`resolveEditableFile()` 还会：

- 拒绝符号链接；
- 解析仓库和文件的真实路径；
- 确认真实文件仍在真实仓库根内。

## 仓库所有权

Windows 上 Git 可能因为仓库所有者和运行账号不同而报：

```text
fatal: detected dubious ownership
```

GitDeck 会使用：

```text
-c safe.directory=<精确仓库顶层路径，使用正斜杠>
```

普通仓库操作不使用 `safe.directory=*`。

## 可选索引锁

读取、状态和还原操作设置：

```text
GIT_OPTIONAL_LOCKS=0
```

这样 Git 不会因为没有权限创建 `.git/index.lock` 而失败。真正修改索引的 `git add` 和 `git commit` 仍然需要正常写入权限。

## 陈旧索引锁的自动清理边界

`index.lock` 是 Git 的原子保护，没有 `--force` 可以绕过。`src/index-lock.js` 只在**用户主动触发的 git 命令失败后**处理，且必须同时满足：

- 命中的是 Git 的锁冲突文案（不是任意包含 `index.lock` 的错误）；
- 锁文件位于真实 Git 目录内（`.git` 目录，或 `.git` 文件里 `gitdir:` 指向的目录）；
- 以 `FileShare.None` 独占打开成功，即当前**没有任何进程持有该文件**；
- 删除后只重试一次，不成循环；清理事件写入 `data/server.log`。

只要进程仍持有锁、独占探测失败、Git 目录无法确定，或锁文件出现在工作树里，就**不删任何文件**，改以 423 报错并列出可能占用的进程。探测脚本用 `-EncodedCommand` 执行、路径通过环境变量传入，避免命令注入。此逻辑不扫描、不巡检、不定时触碰用户仓库。

## 文件编辑

- 二进制文件和超过 512 KB 的文件会被拒绝。
- 保存请求必须携带内容哈希。
- 哈希不一致返回 HTTP 409，而不是覆盖。
- 读取时记录换行格式，保存时保持 LF/CRLF。
- 拒绝符号链接。

## 破坏性界面操作

以下操作必须明确确认：

- 还原或删除文件改动；
- 从工作区移除仓库；
- 删除工作区；
- 删除本地分支；
- 强制删除未合并的本地分支 `-D`；
- 可选删除远程分支；
- 切换文件时放弃未保存编辑；
- 批量移除仓库。

从工作区移除仓库只修改元数据，不对仓库目录调用文件删除。

## 部分失败

批量删除分支可能部分成功。服务端通过 `warnings` 返回失败信息，UI 使用警告提示，不能误报全部成功。

强制删除未合并分支默认关闭。只有用户明确勾选“强制删除未合并分支（-D）”后才执行：批量删除弹窗用 `#forceDeleteBranches`，提交历史徽标右键「删除引用」用 `#forceDeleteRef`，两者默认都不勾选，勾选后分别传 `forceDelete` / `force` 给后端。

## 已知边界

- 除 localhost、会话令牌和来源校验外，没有多用户认证。
- 注册仓库中的 Git hooks 仍会由 Git 在服务账号下执行。
- 没有密钥扫描或凭据存储。
- 没有病毒或文件内容安全扫描。
