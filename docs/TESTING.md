# 测试与验证

## 自动化测试

运行：

```powershell
node --test
```

当前测试套件：

### `tests/project-files.test.js`

覆盖：

- `start.cmd` 使用 CRLF，避免 `cmd.exe` 拆坏命令；
- `.gitattributes` 持续固定 `.cmd` 使用 CRLF；
- 仓库工具栏保留 TortoiseGit 外部打开入口；
- 拖拽排序写入 `orders`、看门狗默认常驻、前端心跳补发、文件日志与全局异常兜底等源码约束；
- 目录选择器的 passive 滚动监听、无重复 DOM 写入、重绘隔离，以及「无后台自动抓取 / 无前端定时刷新」的防回归断言；
- 多选批量添加：只在添加仓库启用、切换目录不清空选择集、关闭时清空、增量更新不重建列表、批量上限与失败项保留；
- 扫描结果的全选 / 反选入口、仓库名拼接展示、悬停完整路径、0 选中禁用添加按钮、勾选增量更新不重建结果列表；
- `.sln` 解决方案模式：并发汇总所有仓库并按仓库缓存、范围/关键字过滤、搜索与范围工具条、重新扫描、空态可恢复、双击按条目所属 `repositoryId` 打开、`GET solutions` 与 `openVisualStudio` 的后端契约，以及「只扫当前仓库」旧实现的防回归断言；单击选中不重建列表 DOM（`selectSolutionItem` 内不得出现 `renderChanges` / `fileGroups.innerHTML`）、双击双通道与去重、打开不走 `performRepoAction` busy 队列、即时反馈与失败提示；
- 提交历史分支标签右键菜单：历史行 `data-commit-hash` 与徽标 `data-ref*` 数据通道、两类菜单共用渲染器与按上下文分发、只有命中徽标才拦截右键（不存在 `openCommitMenu` / `type: "commit"`）、`switch-ref` 主操作走 `checkoutRef`、远端跟踪分支与 `origin/HEAD` 解析、引用级动作登记及提交级动作（`cherryPick` 等）已移除、剪贴板回退、`GET commit` 三种比较模式与根提交回退、宽菜单样式与「菜单内部滚动不误关」守卫。

交互类改动另用 CDP 驱动真实浏览器点击验证（勾选 → 跨目录 → 批量添加 → 后端落盘与前端列表；右键徽标 → 菜单项、确认弹窗、差异弹窗；右键历史行非徽标处 → 不弹自定义菜单）。探针脚本和 Chrome profile 放在 `.workbuddy/scratch/`，验证完用 `node tools/clean-scratch.js` 清理，不入库。

## 手工 UI 验证矩阵

### 工作区

1. 打开自定义工作区下拉。
2. 在两个工作区间直接切换，确认不弹窗。
3. 创建新工作区。
4. 在工作区间移动仓库。
5. 单个和批量从工作区移除仓库，确认磁盘目录仍存在。

### 文件和 Diff

1. 点击变更文件，确认内联 Diff。
2. 在文件夹视图和平铺视图间切换，确认勾选和 Diff 状态保留。
3. 刷新页面，确认上次文件视图仍保留。
4. 切换已暂存、未暂存、未跟踪筛选。
5. 勾选文件，确认批量暂存和还原。
6. 切换编辑器，修改后按 `Ctrl+S` 保存。
7. 从外部修改文件后再次保存，确认 HTTP 409 冲突。
8. 检查 LF 和 CRLF 文件不会整体重写。

### 选中提交

1. 修改至少三个文件。
2. 勾选其中两个。
3. 填写提交说明。
4. 确认按钮显示“提交 2 个选中文件”。
5. 提交。
6. 用 `git show --name-only HEAD` 确认只包含两个选中文件。
7. 确认未勾选改动仍然保留。

### 分支

1. 按分支名和作者搜索。
2. 点击非当前分支行，确认整行勾选并高亮。
3. 点击行内删除按钮，确认选择计数不变且删除弹窗打开。
4. 选择多个分支并打开删除弹窗。
5. 确认当前分支不能选择。
6. 在临时仓库中删除带本地裸远端的合并分支，确认本地和远程均消失。
7. 确认未合并分支会被 `-d` 安全拒绝。
8. 勾选强制删除 `-D` 后，确认未合并分支只在明确确认后删除。

### 右侧提交历史

1. 首次打开仓库，确认右侧默认显示提交历史。
2. 切换“分支”，确认历史隐藏、分支搜索和列表出现。
3. 切回“提交历史”，确认默认选中“所有分支”。
4. 确认多条彩色轨道、连接线和分支/远端徽标可见。
5. 切到“当前分支”，确认图线变为单分支历史。
6. 刷新页面，确认重新默认显示提交历史和所有分支。

### 布局

1. 拖动三个分隔条。
2. 刷新后确认宽度保留。
3. 双击分隔条恢复默认。
4. 聚焦分隔条后用方向键调整。
5. 390 px 下确认分隔条隐藏，页面没有横向溢出。

## 浏览器验证说明

使用无头 Chrome 验证时：

- 使用 `.workbuddy/scratch/` 内的独立 `--user-data-dir`；
- 添加 `--no-sandbox --disable-gpu --disable-software-rasterizer`；
- 需要 CDP 时添加 `--remote-debugging-port` 和 `--remote-allow-origins=*`；
- 写入 Git 状态的流程必须使用 `<repo>/.workbuddy/scratch/` 内的临时仓库；
- 验证完成后清理元数据和目录；
- 完成流程后确认控制台没有 error。

## 测试数据规则

- 所有临时目录、测试仓库、裸远端、Chrome profile 和探针脚本**一律放在 `.workbuddy/scratch/` 内**，用 `node tools/clean-scratch.js --new <prefix>` 创建。
- 不再在项目根目录创建 `.tmp-*`、`.ui-*`、`.chrome-*` 等散落目录。
- 不再把测试仓库放到 `<repo>` 之外的父目录、用户目录或系统临时目录。
- 清理只运行 `node tools/clean-scratch.js`；删除工作目录内指定目标用 `--path <repo 相对路径>`；不使用 `rm -rf` 或通配符批量删除。
- 清理命令单独执行，不拼 `&&` / `;` / `|` 复合命令，避免命令白名单失效重新触发审批。
- `tests/clean-scratch.test.js` 覆盖 `--path` 越界拒绝、受保护目标拒绝、dry-run 不落盘、`.gitkeep` 保留与项目级白名单范围。
- `data/repositories.json` 是用户数据，测试不得重置；禁止在用户业务仓库上执行破坏性验证。
